# KIO Windows 업데이트 배포

Google Drive 데스크톱에 **배포자 본인 계정**으로 로그인합니다. 일반 앱 사용자는 Google 로그인·개발자 키·Cloud 설정이 필요 없습니다. 현재 도구는 Drive 데스크톱의 정상 동기화를 이용하며, 새 ZIP의 링크 공유 설정과 링크 복사는 배포자가 Drive 화면에서 한 번 수행합니다. 서버 API 토큰을 앱에 넣지 않습니다.

## 최초 준비

1. `G:\내 드라이브\ADMIN\KIO-배포키`를 동기화합니다. 이 폴더와 상위 ADMIN은 소유자만 접근해야 합니다.
2. `release-config.example.json`을 `release-config.json`으로 복사하고 실제 Drive 드라이브 문자와 폴더 경로를 맞춥니다. 고정 feedId와 publicKey는 변경하지 않습니다. 비밀번호는 설정 파일에 넣지 않습니다.
3. KIO Windows 이동용 ZIP을 풀어 프로그램 폴더를 준비합니다. 그 안의 Python과 cryptography를 사용하므로 별도 Python/API 키 설치가 필요 없습니다.
4. `kio-update-signing-private.encrypted.pem`의 비밀번호를 본인이 별도로 보관합니다. 암호화된 PKCS#8 파일만 Drive에 둡니다. 기존 공개키 `L1MEbjag8uGWGER+oAdjTk2mq0B/Rx4nQ/Niy1H6U10=`와 다르면 배포가 중단됩니다.

## 다음 Windows 버전 배포 예시

실제 Windows에서 기능 수정 후 새 실행 파일을 빌드해야 합니다. 공통 Python VERSION, UI package 버전, Windows 리소스와 네이티브 endpoint 버전을 맞춥니다. Mac 전용 소스나 기존 Mac ZIP 버전을 Windows 배포에 맞춰 올릴 필요는 없습니다.

```powershell
& 'G:\내 드라이브\ADMIN\KIO-배포키\Publish-Windows.ps1' `
  -Version '4.4.7' `
  -Zip 'C:\KIO-build\KIO-Control-4.4.7-Windows-Portable.zip' `
  -ProgramRoot 'C:\KIO-build\KIO-Control-Windows' `
  -Config 'G:\내 드라이브\ADMIN\KIO-배포키\release-config.json' `
  -Notes '수정 사항을 적으세요'
```

버전·경로는 실제 빌드에 맞춥니다. PowerShell 실행 정책이 회사에서 관리되면 담당 관리자에게 승인된 스크립트 실행 방법을 요청하세요. 도구는 실행 정책을 변경하지 않습니다.

실행 순서:

1. ZIP 경로·개인키/사용자 자료 제외·Windows PE 리소스 버전·Python 버전·SHA-256·크기를 검사합니다.
2. Drive의 윈도우용 폴더에 버전별 ZIP을 복사합니다. 같은 이름의 다른 파일을 덮어쓰지 않습니다.
3. Drive 업로드 완료를 기다린 후 **그 ZIP만** ‘링크가 있는 모든 사용자 / 뷰어’로 공유하고 링크를 입력합니다. `-ZipUrl '공유 링크'`로 미리 전달해도 됩니다.
4. 로그인 없는 다운로드로 ZIP 전체 해시와 크기를 비교합니다. 동기화가 덜 됐거나 공유가 제한돼 있으면 게시하지 않습니다.
5. 비밀번호를 보이지 않는 입력창에 직접 입력합니다. 키는 메모리에서만 복호화하고, 원래 공개키와 일치하는지 확인한 후 서명합니다.
6. 기존 안내를 로컬에 백업하고, 기존 latest.json을 **삭제·이름 변경 없이 같은 파일에 씁니다**. 고정 ID에서 새 서명 내용이 내려오는지 확인합니다. 실패하면 자신의 변경분을 이전 내용으로 되돌립니다. 동시 배포자가 변경했으면 덮어쓰지 않습니다.

성공 메시지 전에는 배포 완료로 판단하지 마세요. 동시에 두 컴퓨터에서 게시하지 마세요. Drive의 캐시·전파 지연 때문에 게시 확인에 최대 3분이 걸릴 수 있습니다.

## 운영체제별 업데이트와 구형 앱 호환

고정 안내 파일 ID: `1p91Pj2v2RhhnSG0rxOxBJW_oBvGjuGqd`

서명된 형식 1 안내의 최상위 version/packages는 전환용 **실제 Windows/Mac 4.4.6 ZIP**을 가리키며 계속 보존합니다. 새로 추가한 서명 필드 `platformReleases`에 운영체제별 version/notes/package를 기록합니다.

- 구형 앱: 모르는 추가 필드를 무시하고 4.4.6을 설치합니다.
- 4.4.6 이상 앱: platformReleases에서 자신의 운영체제 버전만 비교합니다.
- 이후 Windows 4.4.7 게시: Windows 항목만 변경하고 Mac 항목과 구형 앱용 전환 패키지는 그대로 둡니다.
- 구형 Windows 사용자는 4.4.6 전환 후 다시 확인하여 그 이후 Windows 버전을 받을 수 있습니다.
- 오래된 전환용 ZIP 두 개를 삭제하거나 공유 해제하면 아직 전환하지 않은 사용자가 업데이트할 수 없습니다.

앱은 실행 15초 후와 실행 중 하루마다 새 버전을 확인합니다. 설정에서도 직접 확인합니다. 설치는 사용자가 다운로드·다시 시작 버튼을 누를 때 진행하며, 작업/녹화 중에는 설치하지 않습니다. X로 창을 닫으면 백그라운드 앱이 남고, 메뉴의 종료는 프로그램 전체를 종료합니다.

## 실패와 복구

서명/버전/ZIP/공개 다운로드 검사 실패는 feed를 변경하기 전에 중단됩니다. 게시 후 확인 실패는 자신이 쓴 로컬 feed만 이전 내용으로 복구합니다. Drive 동기화가 오프라인이면 원격 복구까지 즉시 보장할 수 없으므로 연결 복구 후 고정 링크의 내용도 확인하세요.

백업: `%LOCALAPPDATA%\KIOControl\ReleaseBackups\latest-before-버전-시각.json`

복구가 필요하면 기존 latest.json의 내용을 백업 내용으로 교체하고 동기화 완료와 고정 링크를 확인하세요. 기존 파일 삭제/재생성은 금지합니다. 설치 도중 교체 실패는 앱 updater가 이전 프로그램 폴더로 되돌립니다. 설치 완료 후 앱 동작 불량까지 자동 판정하는 건강 상태 롤백은 현재 구현 범위에 포함되지 않습니다.

## Windows 실제 검증 이어가기

Mac에서는 Windows 실행 파일의 크로스 빌드와 PE 버전·패키지 검사만 가능합니다. 실제 Windows에서 다음을 확인한 후 운영 배포하세요.

1. 4.4.6 실행, 여섯 단축키 변경·사용 안 함·X 닫기·완전 종료·재실행 유지.
2. 일반/AI 연속 캡처, 복사·저장 후 닫기, 모니터별 녹화·부분 녹화·일시정지·재개·MP4 재생.
3. 구버전 설치본에서 공개 feed 확인→4.4.6 다운로드→설치→재시작 및 로그인·설정 유지.
4. 별도 테스트 Drive 파일에서 게시 성공·접근 제한·동기화 지연·복구 확인. 고정 운영 feed에 가짜 높은 버전이나 검증용 ZIP을 게시하지 마세요.
5. 실제 다음 버전을 만들었을 때 위 명령으로 Windows 단독 게시. Mac 항목이 바뀌지 않고 Windows 항목만 증가하는지 서명 재검증.

배포 키 비밀번호를 잊으면 암호화 백업을 복호화할 수 없습니다. 원래 Mac 키는 그대로 보존되어 있으며 새 키로 기존 앱의 신뢰 관계를 대체하지 않습니다. 이 키는 업데이트 안내 서명용이고 Apple 앱 서명·공증 인증서와 별개입니다.
